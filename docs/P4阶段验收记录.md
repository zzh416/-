# P4 发布准备阶段验收记录

验收日期：2026-10-24

结论：P4 已完成，当前版本达到本机单用户发布门槛。

## 1. 交付范围

P4 不增加 AI 答案生成功能，交付内容是稳定运行、安全与诊断、备份恢复、性能基准和安装文档：

- 默认 Compose 使用构建产物，API 关闭热更新，API/Worker/Web 不再挂载源码。
- `docker-compose.dev.yml` 单独恢复源码挂载和 Uvicorn/Vite 热更新。
- API、Worker、Web、renderer 均使用健康检查；应用容器使用非 root 用户、只读根文件系统、`no-new-privileges`、capability 收紧、内存/进程上限和日志轮转。
- API 为每个响应返回 `X-Request-ID`、`Cache-Control: no-store` 和基础浏览器安全头；访问日志只记录方法、路径、状态、耗时和请求 ID，不记录查询参数、正文或 Key。
- Web 由无第三方运行时依赖的 Node 静态服务器提供构建产物和同源 `/api` 代理，并设置 CSP 等安全头。
- `backup.ps1`、`verify-backup.ps1`、`restore.ps1` 覆盖 PostgreSQL 与 `data/`，不备份密钥；备份会拒绝在后台任务未完成时运行并短暂停写，以保证数据库和文件一致，恢复前自动保存现状，失败时切回旧数据库和旧目录。
- `p4_performance.py` 在一次性数据库中生成 5,000 道题、20,000 个来源块并测量题库查询。

## 3. 备份与恢复证据

在当前真实 Compose 环境执行：

1. 导出 PostgreSQL custom dump。
2. 归档 `data/` 中 4 个文件，共 907,312 字节。
3. 校验两个文件的 SHA-256、长度和归档路径。
4. 将数据库恢复到一次性数据库，确认 Alembic 头为 `20261022_0013`。
5. 将 `data.tar` 解压到一次性目录，文件数和总字节数与清单一致。
6. 执行正式恢复演练；恢复前自动创建 `backups/pre-restore/...`，数据切换后 API 恢复就绪，旧副本才被删除。
7. 人为修改测试副本后，校验脚本因 SHA-256 不一致拒绝该备份。

备份明确不包含：

- `infra/.env` 与模型 API Key；
- Redis 队列数据；
- 构建镜像和可重新生成的前端产物。

Redis 仅承载可重新创建的临时任务状态。恢复后会清空 Redis，避免旧任务引用已替换的数据库状态。

## 4. 性能结果

环境：Docker Desktop 本机容器、PostgreSQL 16/pgvector、FastAPI TestClient 与一次性数据库。每个场景预热 3 次、测量 30 次；数据为 5,000 道题、其中 2,500 道有答案，以及 20,000 个来源块。

| 场景 | p50 | p95 | 最大值 | 门槛 |
| --- | ---: | ---: | ---: | ---: |
| 题库首页 | 26.69 ms | 39.32 ms | 40.93 ms | p95 ≤ 1,000 ms |
| 有答案筛选 | 28.60 ms | 41.62 ms | 41.77 ms | p95 ≤ 1,000 ms |
| 题目/答案关键词搜索 | 35.09 ms | 60.73 ms | 214.88 ms | p95 ≤ 2,000 ms |
| 第 200 页 | 21.15 ms | 33.86 ms | 35.24 ms | p95 ≤ 1,000 ms |

四项均通过。该结果反映当前机器和合成数据，不是公网延迟承诺；若真实题量显著超过该规模，应重新运行脚本，再依据查询计划增加索引或更换分页方式。

## 5. 依赖和安全审计

- Web `npm audit --omit=dev`：0 个已知漏洞。
- renderer `npm audit --omit=dev`：0 个已知漏洞。
- API `pip check`：依赖一致。
- 首次 `pip-audit` 发现 `pypdf 6.21.1` 的 3 个已知 CVE；已升级并锁定为 `6.21.2`。
- 升级后重新运行 `pip-audit`：0 个已知漏洞；最终完整后端测试为 `293 passed`。
- 端口仍只绑定 `127.0.0.1`；PostgreSQL、Redis 和 renderer 不发布宿主机端口。

## 6. 稳定性与持久化

- 六个服务在稳定模式下均达到 `healthy`。
- Web 首页、CSP、安全头和同源 `/api/v1/health/ready` 代理返回 200。
- 创建临时资料库后重启全部 Compose 服务，重启后记录仍存在；验收记录随后删除。
- 六个服务的日志均按每文件 10 MiB、最多 3 个文件轮转，避免长期运行无限占用磁盘。

## 7. 发布边界

- 当前是 localhost 单用户版本，没有登录系统。开放到局域网或公网前必须增加身份认证、HTTPS、会话与 CSRF 防护，并重新做权限验收。
- 现有模型调用会把用户明确选择的资料发送到配置的云端服务；Key 仅保存在 `infra/.env`。
- 当前没有长截图、真实扫描 PDF 和图文混排 Word 样本，这三类保持延期补验；普通截图、DOCX、旧 DOC、文本型 PDF、静态网页和动态网页已有验收证据。
- 当前版本不生成缺失答案。AI 答案草稿、引用验证与费用配额属于下一版本。

```powershell
.\infra\backup.ps1

docker compose -f infra/docker-compose.yml exec -T api python scripts/p2_live_smoke.py

npm.cmd --prefix frontend run lint
npm.cmd --prefix frontend run build
npm.cmd --prefix services/renderer test
```

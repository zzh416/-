# 简历项目与已有题目关联

状态：已实现并验收（2026-10-25）。此项是 P4 后改进路线第三步。

## 行为与范围

技能、排除偏好仍先决定哪些题进入清单及答案是否适用。对留下的题目，额外根据题干与已确认项目共有的技术／主题给出关联建议，并展示共有主题作为依据。关联不修改分数、顺序、题目或答案，不自动生成追问或缺失答案。

画像新增独立项目列表：支持手动添加、编辑、确认、排除及删除。AI 提取画像时同时提取项目名称和逐字原文；无法回指原文的候选不保存，模型项目默认待确认，只有已确认项目参与关联。旧简历可手动补充项目，不要求重新上传或覆盖已确认技能。项目只保存在个人画像中，不进入公共题库。

第一版关联是可解释的确定性建议，不宣称理解项目的全部业务语义。使用既有技术词典及独立的 RAG／向量检索／重排／多 Agent 等主题词；匹配只看题干，不因为答案提到某技术就关联。没有匹配的题目保留为“未匹配项目，可作通用复习”，不丢弃通用基础题。待确认、已排除项目不参与匹配。

清单支持按项目或未匹配项目筛选，并继续与答案、关键词、进入／排除筛选组合。Markdown 默认仍导出全部进入清单题目，同时附上保存的关联建议；不会因页面项目筛选而少导出。旧清单缺少关联快照时明确显示未记录。

## 数据与接口

- `ProfileVersion.projects`：有上限的 JSON 项目快照（最多 20 项），包含稳定 ID、名称、说明、来源、原文证据、原简历版本与确认状态。编辑任何画像字段时保留项目；每次项目修改创建画像新版本。
- `RecommendationRun.profile_snapshot.projects`：保存当时的项目及关联规则版本；`RecommendationItem.project_matches` 保存关联项目 ID、名称和共有主题。历史清单不随项目修改而变化，新关联规则令旧清单提示重新生成。
- `POST /api/v1/profiles/me/projects`、`PUT/DELETE /api/v1/profiles/me/projects/{id}`：沿用画像 owner 隔离、提取中锁定和 `expectedVersion` 并发检查。
- 清单列表增加 `projectId` 或 `unmatchedOnly` 查询，不能同时指定；全部筛选在分页前执行。

## 验收

验证：项目增删改查／版本保留／跨用户访问／并发冲突；模型项目原文校验及待确认状态；多项目关联、答案不误关联、无匹配通用题保留；技能排除优先；历史快照、跨页项目筛选及 Markdown。运行独立临时数据库测试，不污染个人资料。最后构建并备份升级，核对浏览器入口。

命令沿用项目隔离脚本、前端 `npm.cmd run lint` 和 `npm.cmd run build`。本步骤不自动调用真实简历的外部模型进行验收，先用合成资料验证模型协议。

## 使用步骤

1. 刷新页面，打开“我的画像”，找到“4. 我的项目”。
2. 添加项目名称和实际使用的技术／方案，设为已确认；已有简历不需要重新上传。下次“AI 提取画像”也会提取带逐字证据的项目，但重新提取会建立新的待确认技能与项目，请核对后使用。
3. 打开“我的复习清单”，点击“重新生成”。通过项目下拉框查看关联题目，展开“项目关联建议”查看题干与项目的共有主题。
4. “未匹配项目／通用复习”保留没有匹配的题目。统计栏显示整份清单数量，下方“当前筛选共 N 题”显示当前筛选范围。
5. 项目修改或排除后重新生成；旧清单仍保留原关联。Markdown 导出包含已有的项目关联建议，并继续导出整份进入清单的题目。

没有项目、没有项目匹配、旧清单未记录关联是三种不同情况：无项目时可补充；无匹配继续通用复习；旧清单需要重新生成才能保存项目关联数据。

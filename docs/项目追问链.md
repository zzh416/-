# 项目追问链

状态：已实现并验收，2026-10-26。前置基线：319 项隔离回归通过，迁移0015、来源追溯、项目关联和 Markdown 导出已交付；六服务健康，当前 DeepSeek 文本模型已配置。

## 范围与使用约定

在复习清单的项目筛选旁提供明确标注的“项目追问链”入口。用户选择已确认项目及最多3道进入清单、已关联此项目的种子题；每道种子题最多生成3层递进问题。不生成答案，不自动加入题库或改变既有排序及筛选。

种子题标记为“已有题目”，保留其来源快照；用户手写题不伪称原文题。追问标记为“AI 推演，非原文面试题”。每条保留项目说明和种子题的逐字引用及位置；这些引用只证明输入依据存在，不等于证明 AI 问题在原文出现或业务判断正确。

生成仅发送选中项目的名称、说明、所选种子题题干及必要筛选约束到已配置文本模型；不发送完整简历、联系方式、答案或私人备注。用户点击生成前界面显示传输范围，沿用 GLM/DeepSeek 配置。测试和真实模型冒烟使用合成资料。

## 输入与结果边界

- 新生成要求清单为当前版本、项目已确认、所选题目已进入清单且与该项目关联；不允许跨用户／跨清单题目。最多3种子题，输入总量上限20000字符。
- 生成异步执行，持久化等待／处理中／部分成功／成功／等待配置／失败；幂等创建，同一用户同一清单只允许一个生成任务运行，避免重复费用。失败后最多3次手动重试，重复队列消息不重复生成。
- 返回严格 JSON，限定种子ID、层级1–3、问题与双重逐字引文。校验未知ID、短/不存在引文、重复题、非问题、越级、断链及技能／排除偏好；不合格项舍弃，保留其他有效链并披露舍弃数量。
- 项目和种子题保存固定快照，历史结果只读。画像、偏好、题库在生成前或生成中改变时停止保存新结果并提示重新生成；历史查看显示过期提示。
- AI 追问不混入普通 Markdown 备考包；提供独立追问 Markdown 下载，明确标签、引用依据、模型及历史信息。普通清单导出范围保持原约定。

## 接口与存储

新增 `project_followup_runs` 保存 owner、清单外键、项目／种子快照、结果、状态、模型、规则版本、重试与错误信息。结果最多9条，有界 JSON；原有画像及题目表不改写。

- `POST /api/v1/recommendation-runs/{id}/project-followups`：projectId、seedItemIds，支持 Idempotency-Key。
- `GET /api/v1/recommendation-runs/{id}/project-followups/latest?projectId=...`。
- `GET /api/v1/project-followup-runs/{id}` 与 `POST .../{id}/retry`。
- `GET /api/v1/project-followup-runs?projectId=...`：当前用户该项目最近10次记录，跨清单保存的历史结果也可查看。
- `GET .../{id}/export`：独立 Markdown。

owner 隔离沿用404，过期、运行中或非法状态409，字段越界422。不返回密钥或上游原始响应；日志不记录项目／题干正文。

## 实际使用

1. 刷新页面，打开“我的复习清单”。在“导出 Markdown”旁点击 **项目追问链**。
2. 选择一个已确认项目，选择1–3道已关联的种子题；可用关键词缩小题目范围，超过100题时先搜索再选。
3. 阅读传输范围后点击“生成项目追问”。后台处理时可关闭，稍后打开会恢复任务；余额、配置或服务异常会显示具体原因，不自动无限重试。
4. 查看“已有题目”下最多3层“AI 推演 · 非原文题”，展开“查看双重依据”核对项目说明和种子题引用。
5. 点击“导出追问 Markdown”下载独立文件。普通备考包不会包含这些 AI 追问。
6. 通过“最近10次生成记录”选择历史结果。依据变化时历史只读；新生成需先更新复习清单。等待／处理中超过10分钟可手动重试，迟到的旧尝试不能覆盖新结果。

若没有可选种子题，请先检查项目已确认、清单已按当前画像重新生成，且确有进入清单的题目匹配该项目。只是在项目说明里增加技术不会让已排除题目重新进入清单。

## 使用限制

逐字引用校验只能证明依据来自所选输入，不能自动验证问题是否合理、是否与业务真正相关。去重覆盖规范化文本，语义近似的问法仍可能出现；AI结果应人工核对，不作为真实面经统计。项目说明为人工填写时，依据属于用户提供的项目描述，不伪称已验证的简历原件。当前不生成答案，不自动入库，不自动搜索网站。

# 批量链接导入

完成日期：2026-10-26。主动搜索面经不进入当前版本，由用户自行选择资料链接。

## 使用方法

1. 刷新页面，选择目标资料库，在“资料”页点击“批量导入链接”。
2. 每行粘贴一个完整的 `http://` 或 `https://` 地址；空白行忽略，每批最多 50 条，单条最多 2048 字符。
3. 点击“导入链接”，逐条查看新建、复用、批内重复、无效链接，以及资料当前解析状态。关闭面板不会中断任务，刷新后可从最近 10 次导入中继续查看。
4. 解析失败可单独重试，沿用资料最多 3 次重试的限制。因服务中断尚未入队的资料可点击“继续提交未排队任务”。
5. 解析成功后点击“打开资料”，检查正文，再使用已有的“AI 自动整理”抽取题目与原有答案。批量导入本身不调用题目模型，不生成缺失答案。

重复链接仅在当前用户的当前资料库内复用。成功、排队、处理或失败的资料都会保留原状态；复用失败资料不会自动消耗重试次数。需要重新解析时请显式重试，或删除不再需要的旧资料后重新导入。

去重只统一协议/域名大小写、默认端口及空路径，保留路径大小写、尾斜杠、查询参数与 fragment。`#/章节一` 和 `#/章节二` 分别保存；`#/`、`#!/` 路由优先使用隔离浏览器。普通 `#段落` 锚点也保留，继续优先静态提取。

链接仍按单页处理，不自动遍历目录、子页面或整个站点。登录状态、验证码与平台访问限制沿用已有提示；批量入口不会共享宿主机浏览器的登录信息。旧资料曾丢失的章节地址需要重新提供正确链接。

## 存储与接口

迁移 `20261026_0018` 新增 `url_import_batches` 和 `url_import_items`。条目关联现有 Asset/IngestionJob，查询时返回实时解析状态；删除资料后，历史条目显示“资料已删除”。批次记录长期保存，界面列出最近 10 批；删除空资料库时关联批次一并清理。

| 接口 | 作用 |
| --- | --- |
| `POST /api/v1/collections/{id}/url-imports` | `{urls: string[]}`，必须提供 `Idempotency-Key`，返回 201 和逐条结果 |
| `GET /api/v1/collections/{id}/url-imports` | 最近 10 批 |
| `GET /api/v1/url-imports/{id}` | 批次详情与实时资料状态 |
| `POST /api/v1/url-imports/{id}/dispatch` | 仅补投递排队中且没有任务标识的资料 |
| `POST /api/v1/assets/{id}/retry` | 沿用现有失败资料重试接口 |

条目序号从 1 开始。合法与无效链接允许混合，单条失败不影响其他条；超过 50 条、字段类型错误、单条原始输入超过 4096 字符或无效 Unicode 编码会整批返回 422。2049–4096 字符的地址逐条标记无效。控制字符地址无效，NUL 以可见转义保存在错误记录中。

同一幂等键重放相同输入返回同一批次，变化输入返回 409。同库批次创建持有资料库行锁，批次、条目和新资料在一个事务内落库，然后逐条投递。进程在落库后退出可通过重放或补提交恢复。任务投递继承现有 Celery 语义，不承诺跨数据库与消息队列的严格恰好一次；已确认入队但 Worker 中断的任务仍需现有运维处理。旧单链接入口保留原行为，与批量入口同时创建相同地址时仍可能产生两份资料。

安全沿用现有公网目标校验、DNS/IP 固定、重定向检查、浏览器沙箱、响应与时间限制；原始链接按文字呈现。校验失败不回显整个请求或异常上下文。

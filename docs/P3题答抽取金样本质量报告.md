## 3. DeepSeek 全文结果与修复后复验

当前生产评估器共用来源校验、候选优先级、题干清理和按精确来源范围去重逻辑。对真实响应离线重放后的结果如下：

| 指标 | Word | PDF |
| --- | ---: | ---: |
| 题目匹配 / 可见题目精确率 | 66/66 / 100% | 66/66 / 100% |
| 有无答案状态正确 | 66/66 | 66/66 |
| 非法或非唯一引文 / 伪题 | 0 / 0 | 0 / 0 |
| 严格答案字符串一致 | **21/66（31.82%）** | **0/66（0%）** |
| 自动门禁 `passed` | **false** | **false** |
| 人工复核：实质答案完整 | 66/66 | 66/66 |
| 人工复核：串题 / 题干尾部答案标签 | 0 / 0 | 0 / 0 |

严格指标仍使用原有 gold 和阈值，没有因换模型而降低门槛。代码字段 `answer_pair_accuracy` 实际判定是规范化后字符串相等，不能直接解释为人工意义的配对正确率。Word 的差异包括纯答案标签；PDF 还包括英语词间空格和换行。去掉纯标签并统一空白后，PDF 剩下 17 题的表格边界符、项目符号及自动列表编号差异，已逐题人工核对。**人工确认内容完整，不代表严格字符串一致或自动门禁通过。**

人工复核忽略纯“答／答案／参考答案”标签、空白和无意义装饰点，保留“核心能力”“特点”“问题”“结论”等内部小标题及实质正文。两张表的全部单元格内容和顺序保留；PDF 仍是原生表格文字，未恢复视觉表格版式。7 处跨页续答全部完整，包括末页的短结尾。

本轮发现并修复两处后处理问题：

- Word 后 5 题把末尾独立“参考答案：”带进了题干。现在只去掉问句末尾的孤立标签，保留“简单介绍。”“举例说明。”等有效要求。
- PDF 同题出现先短后完整的跨页答案候选，原合并保留了短版本。现在只在本次结果中优先采用同一精确题干来源、逐字唯一引用、顺序合法的严格延续答案；新增段不能跳过实质正文或覆盖其他已识别题干。全部候选仍保留用于校验统计。

修复不重写数据库中已经保存的答案，旧答案及人工修改仍受保护。此次验证是修复后的真实响应缓存重放，不是第二次独立模型实跑；也没有在用户题库执行端到端导入。未审校原作者技术答案本身是否正确。

## 4. 历史 GLM Word 部分结果

原始前三批产生 18 条候选，按来源去重后是 **17 道不同题**，均对应原文真题。人工未发现这些题的答案串给另一题，但发现答案不完整：

| 原始去重结果 | 题数 | 说明 |
| --- | ---: | --- |
| 完整 | 10 | 允许去掉“答：”主标签及无意义装饰点线 |
| 内部小标题遗漏 | 5 | 如“特点”“核心能力”“原因”“优化方法” |
| 实质内容缺失 | 2 | Top-K 缺两项；执行流程只有“答：” |

Top-K 的“大则噪声多、小则信息不足”落在分批边界之外，下一批只有答案尾部、缺少题干。Agent 执行流程在第二批只给“答：”，第三批已有完整流程；旧逻辑把标签当已有答案，挡住补齐。

原严格字符串得分为 3/17，它同时惩罚标签、结构差异及正文缺失，**不能称为只有 3/17 配对正确**。报告用语已改为“原文答案完整一致率（严格）”，并保留人工分类。

该次 GLM 运行其余 **49 题未完成有效模型调用**。第四批曾发生结构化响应不合约，随后因 GLM 资源不足而失败；这些不能直接统计为模型漏题。本轮 DeepSeek 全文运行已完成，但不据此宣称 GLM 的全文表现已复测通过。

## 5. PDF 解析修复

第 13 页仅有 `Agent。`，是上一页末题答案的结尾。旧规则把少于 8 字符的原生文本误判为缺文字并送 OCR，OCR 空结果导致整份解析失败。

修复后仅空原生文本进入缺文字兜底；含图片页仍独立触发 OCR。真实文件复测得到 **13 个页块、0 个待 OCR 单元**，末页文字完整保留。

两张表的原生文字顺序正确，但文本提取会损失视觉表格边界。7 处跨页续答现已在 DeepSeek 全文结果中逐项验证，包括题干与答案分处两页、末题答案跨到第 13 页的情况。

## 6. 修复与本地证据

- 保留 PDF 的短原生文本页，避免无必要 OCR。
- GLM 文本、OCR、画像适配器识别 HTTP 429 的业务码 `1113`，明确提示账户余额/资源包不足；其他 429 仍按限流处理，不显示服务商原始响应。
- 过滤独立“答／答案／参考答案”标签，使后续重叠候选可以补齐正文；来源验证先于过滤，生产与评测使用同一规则。“不会”“不知道”和实际正文不被删掉。
- 对已保存的真实候选离线重放后，执行流程可以补入完整正文，17 题的严格完整一致项从 3 项增至 7 项。其余仍有小标题/正文范围差异，该重放不是新的模型调用，也不能补回 Top-K 原本没有抽出的两项。
- 分批在原字符/块数上限内优先避开明确题干，将题干及其多段答案留在同批。真实 Word 235 块仍为 7 批，Top-K 和执行流程现在均完整进入同批。
- 抽取提示要求保留表格、列表和答案内部小标题；本轮 DeepSeek 全文结果已逐项检查，本地测试与真实质量证据分开记录。
- 无带答案样本时报告显示“不适用”；严格文本不一致须人工区分错配、漏段与格式差异。
- Word/PDF 接入时后端隔离回归为 215 项；图片识别接入后完整回归为 **268 passed**，临时数据库已清理。测试屏蔽真实模型密钥，未产生用户题库测试残留；覆盖双服务商配置、错误码、跨批答案延续、非法候选统计、已有答案保护及 PDF 转图。
- 前端此前 lint、build 均通过，本轮图片接入未修改前端；构建存在既有大包提示。API 与 worker 已重新创建，文字使用 `deepseek-chat`，OCR 选择 DeepSeek 的 `deepseek-flash`。

无法识别题干、单题超限、PDF 页内边界不明时仍保留有上限的原策略，不能保证所有长答案完整。既有用户题目、人工修改和历史记录未自动重写；旧错误答案仍通过原文复核修正。

## 7. 模型选择与资源记录

两张截图与 Word 前三批调用成功后，GLM 返回 HTTP 429 / `1113`：“余额不足或无可用资源包”。用户提供新密钥后仍返回相同业务码。本轮按用户要求接入 DeepSeek，并在得到两份真实资料的明确传输授权后完成全文调用。

文字题答、简历画像和质量工具现在通过 `TEXT_MODEL_PROVIDER=glm|deepseek` 显式选择服务商，不自动切换。DeepSeek HTTP 402 单列余额不足，401/403 单列鉴权失败，429 仍是限流；请求和错误处理参照官方 [JSON 模式](https://api-docs.deepseek.com/guides/json_mode/) 与 [错误码](https://api-docs.deepseek.com/quick_start/error_codes/)。独立测试题和虚构简历均调用成功，本轮未发送用户真实简历。

OCR 现通过独立的 `OCR_PROVIDER=glm|deepseek` 显式选择，本机已切到 DeepSeek 并通过普通截图与队列检查；不再要求智谱资源可用才能识别新图片。选择 GLM 时仍需其账户资源。私有原件副本、人工 gold、模型输出及逐题记录仅在本机 `apps/api/.local-quality/`，已被 Git 和 Docker 构建忽略；密钥和原件不提交版本库。

本次真实全文调用命令（本机私有验收脚本，不写入用户题库）：

```powershell
docker compose -f infra/docker-compose.yml run --rm -T --no-deps -e TEXT_MODEL_PROVIDER=deepseek -e EVAL_RUN=deepseek-first api python -u .local-quality/live_file_probe.py sample.docx sample.pdf
```

本机详细记录为 `deepseek-first/review.md`（修复前）和 `deepseek-first/final-review.md`（修复后缓存重放）。后续需要独立重跑时必须使用新运行名，不能把缓存当作新调用结果。

## 8. 门槛与剩余工作

2026-10-22 的 24 道解析后文字金样本真实调用 `glm-4-plus`，召回、可见准确率、答案状态和带答案题的严格一致率均通过当时门槛。它只代表当时文字样本，不涵盖本轮修改后的真实文件全文效果。

门槛维持：原始题目召回 ≥95%、疑似漏题辅助召回 ≥98%、可见题目准确率 ≥98%、答案状态及原文答案完整一致率 ≥95%。本轮严格答案指标未达标，人工核对不能自动替代门禁。下一步需要明确跨格式评测的标签、空白、表格和列表规范化规则，并用真实漏段、串题反例验证不会掩盖错误，再决定如何验收；本轮未改规则或阈值。

长截图、扫描 PDF、图文混排 Word 尚无真实验收证据；同一套 66 题的两种格式不代表所有资料。无答案样本不能证明配对能力，未完成项不记作通过。

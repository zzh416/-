# P3 题目分类与个性化计划及下一版本路线

> 更新时间：2026-10-23
> 状态：P3 当前可取得样本范围与 P4 发布准备均已完成。两张真实普通截图共 27 题已完成 OCR/抽取核对；DeepSeek 已完成 Word/PDF 全文，各覆盖 66 题，排版归一内容门禁均为 66/66。用户当前没有长截图、扫描 PDF 和图文混排 Word，相关验收延期；AI 答案生成留到下一版本

## 1. 版本结论

当前版本按以下两个阶段完成收尾：

- **P3：题目整理与个性化清单。** 从资料中自动抽取问题和原文答案，区分有答案与无答案；读取简历和全局备注，过滤不适合当前用户的题目及答案。
- **P4：发布准备。** 完成安全回归、备份恢复、权限测试、性能测量、安装文档和最终验收。

**AI 答案生成不属于当前版本。** 它作为下一版本最后阶段的候选功能，等当前题目识别、答案配对、个性化筛选和发布质量稳定后再实施。当前版本不会自动或手动补写缺失答案，只有问题的面经始终只显示问题。

## 2. 两层答案状态

资料自身的答案状态与答案是否适合当前用户是两件事，接口和界面需要分别表达。

### 2.1 内容状态 `answerState`

`answerState` 只反映这道题当前保存的有效答案版本：

| 状态 | 判定 | 展示方式 |
| --- | --- | --- |
| `MISSING` | 没有有效答案 | 只展示问题、出处和备注 |
| `SOURCE_ANSWER` | 有原文、知识库或用户手写答案，尚未明确核验 | 展示答案及来源 |
| `AI_DRAFT` | 下一版本预留：只有未确认的 AI 候选答案 | 展示答案并标记“AI 草稿” |
| `VERIFIED` | 用户确认了当前选定答案 | 展示答案、核验人与时间 |

该状态由答案来源、复核状态和有效性计算，不保存一份可独立修改的重复真值。当前版本只会产生 `MISSING`、`SOURCE_ANSWER` 和 `VERIFIED`；`AI_DRAFT` 保留给下一版本。下一版本的优先级预定为：已确认答案 > 非 AI 来源答案 > AI 草稿 > 无答案。

### 2.2 个性化可用状态 `usableAnswerState`

`usableAnswerState` 只在指定画像和偏好规则版本下计算：

| 状态 | 判定 |
| --- | --- |
| `ANSWERED` | 至少有一个答案符合当前用户的技术栈和排除规则 |
| `MISSING` | 没有答案，或已有答案都不适合当前用户 |

例如，一道通用线程题附带 Java 实现答案：资料的 `answerState` 是 `SOURCE_ANSWER`；用户只会 Python 时，个性化清单中的 `usableAnswerState` 可以是 `MISSING`。界面应显示“有来源答案，但当前不适用”，不能把它说成资料原本没有答案。

“全部题库”的有答案/无答案筛选使用 `answerState`；“我的复习清单”的可用答案筛选使用 `usableAnswerState`。

## 3. P3 实施范围

### 3.1 自动抽取和题答配对

- 对导入后的文字块识别问题边界、原文答案边界和两者关系。
- 支持纯问题列表、标准问答、标题加正文、编号列表以及同一资料中混合出现的形式。
- 无法确定答案归属时保留为待复核，不把相邻段落强行配成答案。
- 题目允许答案为空；不写入“暂无答案”等占位文本，也不在 P3 自动调用模型生成答案。
- 保留原始问法、原文答案、资料版本和页码/段落定位，便于回看与纠错。
- 同一道题在多个资料中出现时保留各自出处；规范化去重不能删除来源证据。

### 3.2 有答案/无答案分类

- 在题库列表提供“全部 / 有答案 / 无答案”筛选和数量。
- 列表及详情展示答案来源和复核状态；`SOURCE_ANSWER` 不能包装成已验证答案。
- 删除、拒绝或失去全部引用的答案后，分类结果立即重新计算。
- 迁移 P1 已有手工问答：有答案记录视为 `SOURCE_ANSWER`，空答案记录视为 `MISSING`，现有正文和版本历史不变。

### 3.3 简历和备注驱动的个性化

- 提供独立的“我的画像”入口上传简历，支持现有文件解析能力可读取的格式。
- 从简历提取技能、熟练度候选和项目证据；用户可以确认、修改或删除。
- 保存结构化画像版本，不把完整简历原文当成日常筛选输入；下一版本生成答案时也不默认发送完整简历。
- 支持全局偏好规则，例如“不会 MySQL”“只看 Python”“暂不考虑前端”。
- 硬排除规则先过滤，相关度评分再排序，并显示推荐或排除原因。
- 分别判断题目依赖和答案依赖，避免保留题目后展示不适合用户的语言实现答案。
- 画像、规则或题库内容变化后，使旧推荐结果失效并重新计算；历史运行仍记录当时使用的画像、规则、题目和答案版本。

### 3.4 P3 接口草案

| 接口 | 作用 |
| --- | --- |
| `GET /questions?answerState=ANY|ANSWERED|MISSING` | 查询资料自身的答案分类 |
| `POST /assets/{id}/question-extraction-runs` | 对解析完成的资料启动题答抽取 |
| `GET /question-extraction-runs/{id}` | 查询抽取进度、统计和待复核项 |
| `POST /question-extraction-runs/{id}/retry` | 幂等重试失败或部分成功的抽取任务，最多三次 |
| `PUT /question-extraction-runs/{id}/review-items` | 批量确认、拒绝或重置抽取项，整批执行并校验当前状态 |
| `DELETE /questions/{id}/answer` | 删除错误答案并写入可恢复历史 |
| `GET /questions/{id}/history` | 查询题目、答案和复核状态的修改历史 |
| `POST /questions/{id}/history/{changeId}/restore` | 在并发校验通过后恢复该次修改前的内容 |
| `POST /profiles/resumes` | 上传或选择简历资料并启动画像提取 |
| `GET /profiles/me` | 获取结构化画像及当前版本 |
| `PATCH /profiles/me` | 确认或修正技能和目标岗位 |
| `POST /preference-rules` | 新增全局偏好或排除规则 |
| `POST /recommendation-runs` | 按画像和规则版本生成复习清单 |
| `GET /recommendation-runs/{id}` | 获取题目、可用答案状态和解释 |

接口字段在编码前还需结合现有 P1 单答案模型定稿。P3 可以先保留兼容读写层，再把底层答案扩展为多版本模型，避免一次迁移同时改变前端和抽取任务。

### 3.5 P3 完成标准

- 导入只有问题的资料后，题目全部进入“无答案”，详情没有占位答案。
- 导入同时包含问答和纯问题的资料后，分类数量正确，答案不会错配给相邻问题。
- P1 已有手工题目和答案升级后内容、备注和历史版本不丢失。
- 简历只有 Python、偏好排除 Java 时，不推荐 Java 专属题目或 Java 专属答案。
- 备注“不会 MySQL”时排除 MySQL 专属内容；除非用户明确排除整个数据库领域，否则不连带排除通用事务、ACID 等题目。
- 每个保留、排除和排序结果都能给出可读原因，并记录使用的画像与规则版本。

## 4. 下一版本路线：AI 答案生成

本节只记录后续方向，不进入当前版本的开发排期、验收范围或发布阻塞项。下一版本的前置条件是当前 P3/P4 已发布并积累了真实的题答配对、筛选质量和无答案数量数据。

### 4.1 预定生成入口与上下文

- 在无可用答案的题目详情提供“根据知识库生成草稿”按钮，默认单题、用户主动触发。
- 模型输入只包含当前问题、必要的结构化技能信息、当前生效的偏好、用户选择包含的题目备注，以及检索到的知识片段。
- 简历用于控制表达方式和技术选择，知识库片段作为技术事实依据；默认不发送完整简历原文。
- 题目备注默认不参与生成，用户开启“包含本题备注”后才发送。
- 若没有足够证据，返回“知识库依据不足”并维持缺失状态，不能编造引用。

### 4.2 预定草稿、确认和版本

- 生成结果写入新的答案版本，来源为 `AI_GENERATED`，复核状态为 `DRAFT`。
- AI 草稿不能覆盖原文答案、用户手写答案或已确认答案。
- 用户可以编辑后确认；确认会产生新版本并记录确认时间、使用的画像/规则版本、模型和引用片段。
- 用户拒绝草稿后保留最少审计信息，拒绝内容不参与默认答案选择。
- 相同问题、画像、规则、检索证据和生成参数使用幂等键，重试不重复扣费或写入。

### 4.3 预定成本和失败处理

- 下一版本首期只做按需单题生成；批量补全等单题质量和成本数据稳定后再评估。
- 设置单次输入长度、检索片段数、每日调用量和并发上限。
- 认证失败、限流、超时、内容过长和依据不足分别给出明确错误，可安全重试的任务保留重试入口。
- 保存用量、耗时、缓存命中和失败类型，不记录密钥，也不在普通日志中输出完整简历或敏感备注。

### 4.4 下一版本验收预案

- 只有用户点击后才调用模型；浏览无答案列表不会触发生成。
- 请求只携带必要的结构化画像、偏好、可选题目备注和相关知识片段。
- 生成结果始终标记“AI 草稿”，用户确认前不成为已验证答案。
- 有来源答案时，新草稿不会替换或隐藏来源答案。
- 知识库无依据、模型失败或用户取消时，题目仍保持原状态且不会留下半成品答案。
- 相同请求重试不会产生重复版本或重复计费任务。

## 6. 当前版本不纳入范围

- 不生成缺失答案，也不自动改写来源答案。
- 不提供“根据知识库生成答案”按钮或后台生成接口。
- 不实现 AI 草稿、生成确认流、生成成本配额或批量补全。
- 不把互联网搜索结果直接补成答案。

上述能力全部留到下一版本重新排期。当前版本只展示和筛选资料中已有答案及用户手写答案。

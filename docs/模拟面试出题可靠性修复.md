# 模拟面试出题数量与格式修复

2026-10-26。适用于 AI 自主出题、混合出题；题库出题继续直接使用已有合格题目。

## 问题与原因

只读核对历史记录，确认两轮指定项目的 AI 面试均设置 8 题、实际保留 3 题；一轮混合面试曾手动重试，最终保留 8 题。

旧版存在三个问题：

1. 发给模型的项目列表虽然已经限定范围，但没有明确传递“本轮只问指定项目”。模型可能返回技能基础题，后端却按指定项目规则拒绝这些题。
2. 只请求一次模型，过滤重复题、排除技术或依据不合格题后直接结束，没有继续补缺。
3. 整批校验模型结果，一道题的可空字段、格式等不符合约定，就可能让整批出题失败。

历史记录没有保存当时的模型原始返回及拒绝计数，因此无法还原旧 5 道题各自被丢弃的确切原因，也不能确认历史格式错误的具体字段。修复依据是已确认的记录现象、代码缺口和可复现测试。

## 当前行为

- 明确向模型传递所选项目 ID、允许的依据类型、总目标题数和本次缺额。指定项目时必须使用该项目的原文片段。
- 系统从项目说明生成带编号的原文片段，AI 选择片段编号，系统回填实际原文；不要求 AI 重新抄写长引文。题目须与所选片段的技术主题、工具名称或具体中文技术短语匹配。项目内的 PyMuPDF、RRF、Ragas 等名称可以作为依据，不要求先加入全局技能词表。
- 兼容旧式引文时只忽略空白差异，并映射回实际原文；不接受语义改写、伪造引文或无关问题。
- 保留通过校验的题目与顺序，只请求剩余题数，最多自动请求 3 次。传递已保留题及上一轮的校验原因，避免重复。
- 逐条验证题目；保留合格条目，将可空字段的空字符串规范为 null。仅支持剥去包裹整个 JSON 的 Markdown 代码围栏，不从任意说明文字中猜测 JSON。
- JSON/结构错误或输出截断可在本次次数限制内自动重试；鉴权、余额和服务错误不自动反复请求。已有合格题仍会保留。
- 每次规划模型的 HTTP 超时配置为 60 秒；自动尝试与手动补题均可能产生模型 API 费用。
- 页面显示“出题检查详情”：目标、实际保留数、模型请求次数、格式问题和重复/依据/偏好等拒绝原因计数。日志和诊断只记录计数、错误码及安全字段路径，不记录原始模型响应。
- 仍不足时明确显示缺额。尚未开始的 AI/混合面试可点“补足目标题数”，保留原题后继续补缺；手动重试与补题合计上限 3 次，每次仍最多请求模型 3 次。
- 不放宽已确认技能、排除偏好、项目原文依据、主题相关性和重复校验来凑够题数。依据不足或模型持续无效时仍可能少于目标，可开始现有题或调整画像后新建。

## 用户怎么验证

1. 刷新页面，新建一轮面试，选择 AI 自主出题、一个已确认项目、8 道基础题及备考预览。
2. 生成后核对“已准备”数量；展开“出题检查详情”查看是否发生补题及过滤。
3. 若仍不足，在开始作答前点击“补足目标题数”，检查原题保留、只追加缺额。
4. 混合模式同样检查上述流程；题库足够时会优先保留题库题。

已开始或已结束的历史面试不会自动追加或替换题目，原有 3 题记录仍按当时内容保留。

## 追加修复：实际项目的引文与主题误拒绝

用户再次反馈综合 AI 出题首次只有 4 道，手动补题后只有 5 道。新诊断确认：首次三次请求累计主题拒绝 9 条、引文拒绝 5 条；手动补题三次请求累计主题拒绝 5 条、引文拒绝 6 条，格式错误为 0。此次范围为综合，不能归因于前述指定项目范围缺失。

代码与复现测试证明：原主题词表未覆盖多个项目工具/短语；项目说明中的不规则空格和单词内换行，也会使抄写式引文不一致。上一轮的限次补题机制正常工作，但不能纠正这些依据校验缺口。历史诊断只保存计数，不能断言每个被拒条目都属于误判。

新增 `interview_project_evidence.py` 和模型字段 `project_evidence_id`，实现上述服务端片段回填与项目原文术语校验。片段编号绑定项目和原文；错误编号、其他项目、无关问题、排除技术仍被拒绝。技能与偏好规则及复习清单项目分类算法不变。

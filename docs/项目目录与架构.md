# 项目目录与架构

本项目面向从 GitHub 克隆后在个人电脑本地运行的场景。所有对外端口默认只绑定 `127.0.0.1`，不要求公网服务器。

## 目录职责

```text
interview-knowledge-hub/
├── frontend/              React、TypeScript、Vite 用户界面
├── backend/               FastAPI、Celery、数据库模型与迁移
├── services/
│   └── renderer/          Playwright 动态网页渲染服务
├── infra/                 Compose、环境配置模板、备份与恢复
├── data/                  上传原件和解析产物，本机私有、Git 忽略
├── backups/               本地备份，本机私有、Git 忽略
├── docs/                  架构、功能边界和验收说明
├── tasks/                 阶段计划与历史任务记录
└── tests/                 跨服务测试夹具
```

### `frontend/`

只负责浏览器界面和前端状态：

- `src/components/`：资料、画像、复习清单、模拟面试等界面组件。
- `src/api/`：调用后端 API 的客户端和 TypeScript 类型。
- `public/`：前端静态资源。
- `Dockerfile`、`package.json`：前端构建与依赖。

前端不直接访问数据库、Redis 或模型服务。

### `backend/`

负责业务规则、数据持久化和后台任务：

- `app/routes/`：HTTP 接口。
- `app/schemas/`：请求和响应合约。
- `app/modules/`：资料解析、题答抽取、筛选、面试等领域逻辑。
- `app/adapters/`：GLM、DeepSeek、OCR 和渲染器等外部适配。
- `app/models/`：SQLAlchemy 数据模型。
- `app/workers/`：Celery 后台任务。
- `migrations/`：Alembic 数据库迁移。
- `tests/`：后端单元与集成测试。

API 和 Worker 使用同一套后端代码，因此放在同一目录，由 Compose 以不同启动命令运行。

### `services/renderer/`

这是独立的 Playwright/Chromium 服务，只负责加载需要 JavaScript 的公开网页并返回受限结果。它与主后端隔离，便于单独限制网络、内存和系统权限。

### `infra/`

这里集中放运行环境，而不是业务代码：

- `docker-compose.yml`：稳定运行模式，启动 Web、API、Worker、Renderer、PostgreSQL 和 Redis。
- `docker-compose.dev.yml`：开发模式源码挂载和热更新。
- `.env.example`：可公开提交的环境变量模板；真实 `.env` 不提交。
- `backup.ps1`、`verify-backup.ps1`、`restore.ps1`：备份、验证和恢复。

## 数据库放在哪里

仓库不建立 `database/` 目录，原因是这里没有需要单独维护的数据库服务源码：

- PostgreSQL 和 Redis 由 Docker 镜像提供，在 `infra/docker-compose.yml` 中声明。
- 实际数据库数据保存在 Docker 命名卷 `pgdata`，Redis 数据保存在 `redisdata`。
- 表结构属于后端业务合约，迁移放在 `backend/migrations/`。
- 上传原件放在根目录 `data/`，备份放在 `backups/`；两者均被 Git 忽略。

执行 `docker compose ... down` 会保留数据卷；除非确定要永久删除本机数据，否则不要执行 `down -v`。

## 运行时关系

```text
浏览器
  └─> frontend(Web :5173)
        └─> backend(API :9000)
              ├─> PostgreSQL（业务数据）
              ├─> Redis（任务队列）
              └─> Celery Worker
                    ├─> data/（上传原件）
                    ├─> renderer（动态网页）
                    └─> GLM / DeepSeek（按配置调用）
```

前端和 API 只映射到宿主机 `127.0.0.1`；PostgreSQL、Redis 和 Renderer 默认不映射宿主机端口。

## 克隆后的最小操作

```powershell
git clone https://github.com/zzh416/interview-knowledge-hub.git
Set-Location interview-knowledge-hub
Copy-Item infra\.env.example infra\.env
docker compose -f infra/docker-compose.yml up -d --build
```

不使用 AI/OCR 时可以保留空 Key，文字、文本型 PDF/Word 和可直接提取的网页仍可使用。需要 AI 自动整理、画像提取、模拟面试或图片识别时，再在 `infra/.env` 配置所选服务商。完整步骤见[启动步骤](../启动步骤.md)。

## 本地隐私边界

- `infra/.env`、`data/`、`backups/`、`.local-quality/` 均不提交 Git。
- 外部模型调用仍会把完成该功能所需的内容发送给配置的模型服务商；这不是纯离线推理。
- 当前是本机固定用户模式，没有面向公网的登录和多租户权限系统，不应直接暴露到公网。

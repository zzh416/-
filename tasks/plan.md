# P3 实施计划：题答抽取与个性化清单

状态：P3 进行中；P3-4、P3-5 和 P3-6 验收自动化已完成，下一步补齐 P3-0 至 P3-3 的剩余质量增强并通过最终检查点。更新时间：2026-10-22。

详细产品范围见 `../docs/P3计划与下一版本路线.md`，P2 差距与验证证据见 `../docs/P2-P2.5复核与P3开工准备.md`。

## 目标

把已解析资料自动整理成可复核的题目和原文答案，明确区分有答案/无答案；再根据用户简历形成的结构化技能画像和全局偏好，生成带解释的个人复习清单。

当前版本不生成缺失答案。只有问题的资料保持无答案，AI 答案生成留到下一版本。

## 实施原则

1. 先保证来源块顺序和定位可靠，再做题答配对，避免模型在错误上下文上产生看似正确的结果。
2. 模型只提出结构化候选；严格校验、来源引用、状态计算和过滤规则由应用控制。
3. 无法确定答案归属时进入待复核，不把相邻段落强行配成答案。
4. 题目依赖和答案依赖分别判断；通用题可以保留，同时隐藏不适合当前画像的语言实现答案。
5. P1 手工题、答案、版本历史和备注必须无损迁移。
6. 每个推荐结果记录画像版本、规则版本和可读原因，画像变化后旧结果失效但仍可追溯。
7. 每项任务控制在约五个文件以内；超过时先拆分为迁移、后端合约、服务逻辑和前端接入等独立步骤。

## 数据与接口边界

- `source blocks` 保存资料版本、顺序、块类型和格式相关定位；抽取只引用块 ID 与字符范围。
- 同一规范化问题可以有多个 `question occurrences`，每个出处独立保留。
- 答案使用候选/版本模型，记录来源、引用块、复核状态和技术依赖；不创建“暂无答案”占位正文。
- `answerState` 表达资料自身是否有有效答案；`usableAnswerState` 表达指定画像下是否有可用答案。
- 简历原文仍作为受保护资料保存；日常筛选读取结构化画像版本，不反复把完整简历发送给模型。
- 偏好规则先支持明确的包含/排除及作用域，避免用任意自然语言直接控制查询。

## 质量门槛

- 纯问题样本不得生成答案；答案归属不确定时必须待复核。
- 混合 PDF 和 DOCX 的块顺序、页/段落定位与原文一致。
- 迁移后 P1 手工答案及历史版本字节级内容不变。
- 只会 Python 且排除 Java 时，不出现 Java 专属题目或仅有 Java 实现的可用答案。
- “不会 MySQL”排除 MySQL 专属题，不误删 ACID、事务隔离等通用数据库题。
- 所有后台任务幂等、可观察、可安全重试；日志不输出 Key、完整简历或完整私人备注。

## 验证策略

- 解析器：固定混合 PDF、DOCX、长截图样本做顺序与完整性断言。
- 数据迁移：在含 P1 问答、历史版本、备注和已删除来源标记的数据库副本上升级/降级验证。
- 抽取：为纯问题、问答交错、标题正文、编号列表和模糊边界建立金样本，统计漏题、错配和待复核比例。
- 筛选：表驱动测试覆盖语言、数据库、通用概念、答案技术依赖和规则版本变化。
- 前端：覆盖加载、失败、空状态、筛选计数、候选复核、画像修正和推荐理由。
- 阶段结束统一运行后端测试、Renderer 测试、前端 lint/build、Compose 配置和真实服务冒烟。

## 明确不纳入 P3

- 生成或改写缺失答案。
- 批量调用模型补答案。
- 登录、验证码绕过或整站爬取。
- 网页图片 OCR；当前要求用户把目标图片单独上传。
- 向量检索和互联网搜索自动补答案。

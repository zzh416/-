## P3-2：自动题答抽取

- [x] T09：实现 GLM 文本模型适配器，使用严格结构化输出、超时、认证/限流错误映射和输入/输出上限。

- [x] T11：校验模型输出只能引用当前资料版本的合法块与字符范围；非法或模糊配对进入待复核。

- [ ] 检查点：只有问题的资料全部为 `MISSING`，混合资料的原文答案引用正确。

当前进度：抽取运行、来源出现记录和待复核状态已落库；创建、查询和最多三次的幂等重试接口已接通。重试复用同一运行，按来源范围跳过已有题目，不覆盖已复核或人工修改内容。独立临时 PostgreSQL 数据库已覆盖 P1 数据升级、降级、再升级。T05 的独立答案候选合约仍未完成。
长网页已经改为带边界重叠的来源块分批抽取；整份资料仍受 60,000 字总上限约束。
题答来源合约现支持标题式问题和跨块的多段答案，应用负责根据逐字引文计算字符范围；单批异常时保留其他批次的有效结果并标记 `PARTIAL_SUCCESS`。仍需在 T13 中用更多真实平台和混合格式样本统计漏题、错配及待复核比例。

当前进度：已完成第一条可用复核闭环。用户可以从抽取结果进入原文对照页，定位问题和答案引文，确认、修改、拒绝或重置候选；拒绝最后一个题目出处后，该题从普通题库隐藏但复核记录保留。系统还会用确定性规则提示带问号、明确问句和编号题目式标题中的疑似漏题，用户可从精确原文范围补建题目。答案修改保留版本记录，题目与复核状态的独立历史、答案删除和批量复核仍待完成，因此 T16、T17 和阶段检查点保持未完成。

## P3-4：简历画像与偏好

- [x] T18：增加“我的画像”入口；简历复用已有安全上传/解析能力，但与面经资料用途分开。
- [x] T19：建立画像及版本、技能候选、熟练度/证据和目标岗位模型；完整简历不作为日常筛选载荷。
- [x] T20：实现画像提取任务与严格校验，用户可确认、修改和删除技能。
- [x] T21：实现全局偏好规则的新增、启停、删除和版本化，首期支持技术包含/排除及作用域。
- [x] T22：建立可维护的技术别名与上下位关系，覆盖 Python、Java、MySQL、数据库通用概念等验收词。
- [x] 检查点：用户能从简历得到可编辑画像，并保存“不会 MySQL”“只看 Python”等规则。

当前进度：简历使用独立的 `RESUME` 资料类型，不属于任何面经/知识库；图片、PDF、Word、Markdown 和 TXT 复用现有解析链路。GLM 只返回带原文逐字证据的目标岗位和技能候选，无法回指原文的候选会被丢弃并标记部分成功。每次 AI 提取、目标岗位修改和技能确认/排除/编辑/删除都会产生新的画像快照。全局规则支持优先/排除、题目/答案/两者作用域、启停和软删除；技术目录区分 MySQL 产品知识与数据库通用知识，并允许自定义技术项。规则已在 P3-5 正式参与筛选。

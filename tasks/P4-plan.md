# P4 实施计划：发布准备

状态：已完成。更新时间：2026-10-24。详细证据见 [`../docs/P4阶段验收记录.md`](../docs/P4阶段验收记录.md)。

## 目标

把 P3 业务闭环整理为可在本机稳定运行、可备份恢复、可诊断且有明确安全边界的版本。

## 执行顺序

1. 为 API 增加请求关联 ID、安全响应头和不含私密正文的最小访问日志。
2. 实现 PostgreSQL 与 `data/` 的备份、验真、恢复前安全备份、数据切换和失败回滚。
3. 在一次性数据库中测量 5,000 题、20,000 来源块的列表、筛选和搜索性能。
4. 将默认 Compose 切换为稳定模式，保留显式开发覆盖文件，并收紧容器权限与资源。
5. 完整回归、依赖漏洞审计、真实队列、全服务重启和持久化验收。
6. 更新 README、启动步骤、架构状态和阶段记录。

## 发布边界

- 仅支持 localhost 单用户；开放网络前必须新增认证、HTTPS 和会话安全。
- Redis 是临时任务队列，不是业务数据备份源。
- API Key 不进入备份、日志、Git 或验收报告。
- AI 生成缺失答案属于下一版本。

# P2 实施计划：文件识别与网页导入

## 目标

在 P1 文字闭环上增加图片、PDF、DOCX、旧 DOC 和静态网页 URL 的可追溯导入。耗时解析由 Celery Worker 执行，前端显示任务阶段、结果和明确失败原因；解析后的文字仍可人工修订并保留版本。

## 边界

- 本阶段负责输入、提取、OCR、任务状态、来源和纠错，不负责简历画像或个性化筛选；后者属于 P3。
- 静态网页只获取无需登录且无需执行 JavaScript 的正文。
- 没有 OCR API Key 时仍允许保存文件，并明确显示等待配置，不能伪装成解析成功。
- 用户文件、网页和模型输出均视为不可信输入。

## 验收主链路

1. 上传图片、文本型 PDF、DOCX，创建异步任务并最终得到可修订文字。
2. 图片 OCR 在配置 GLM Key 后完成；未配置时显示可操作的失败原因。
3. 输入公开静态网页 URL，安全获取正文，保存 URL、抓取时间和快照摘要。
4. `.doc` 无可用转换器、加密/损坏文件、动态或受限网页均明确失败。
5. 任务可查询、可重试，重复提交不重复生成资料版本。
6. URL 不能访问回环、私网、链路本地、保留地址或通过重定向绕过检查。

## 阶段

### Phase 1：合约、迁移与任务骨架

- **Status:** complete

- 增加 P2 数据模型、枚举、迁移与 API Schema。
- 增加原件安全存储、上传魔数/大小/文件名校验。
- 先写失败测试，再实现任务创建、读取和重试合约。

### Phase 2：确定性文件解析

- **Status:** complete

- TXT/Markdown 沿用 P1。
- PDF 提取文本并检测需要 OCR 的页。
- DOCX 提取标题、段落和表格。
- 旧 DOC 使用隔离的 LibreOffice 子进程转换；不可用时明确失败。

### Phase 3：安全网页导入

- **Status:** complete

- URL 规范化、DNS 全量解析、私有/保留地址拒绝、禁用自动重定向。
- 限制响应大小、类型和超时；Trafilatura 提取正文。
- 保存最终来源元数据和抓取时间。

### Phase 4：OCR 与 Worker 编排

- **Status:** complete

- GLM OCR 适配器，密钥只从环境读取，输出经过结构校验。
- 图片及 PDF 需 OCR 页进入统一文本块。
- Worker 阶段状态、进度、错误码、最多三次显式重试和幂等写入。

### Phase 5：前端导入与进度体验

- **Status:** complete

- 文件类型扩展、URL 导入入口、上传限制说明。
- 任务列表/轮询、阶段和失败原因、重试按钮。
- 解析文字查看、来源信息和修订入口。

### Phase 6：完整验收与文档

- **Status:** complete

- 聚焦测试、完整后端测试、前端 lint/build、依赖审计。
- Docker 重建、迁移往返、真实浏览器主链路及安全用例。
- 更新 README、启动文档、架构状态和 P2 验收记录。

# P2.5 发现与决策

## 已确认

- 当前网页链路使用固定公网 IP 的静态 HTTP 抓取和 Trafilatura 正文提取。
- Worker 已经串行执行，适合限制浏览器并发为 1。
- Playwright 浏览器应与 API、数据库、文件和模型密钥隔离；只返回渲染后的 HTML、最终 URL 和标题。
- 用户浏览器登录状态不会自动传入后端浏览器。本阶段使用全新匿名 Context，登录/验证码页面明确失败。
- 对不可信网页，仅在页面路由层检查 URL 仍有 DNS 重绑定窗口；独立无密钥容器与私网地址阻断共同降低影响。

## 统一降级策略

1. 受限静态抓取。
2. Trafilatura 提取正文。
3. 提取为空或检测到 JavaScript 外壳时，调用浏览器渲染。
4. 对渲染后的 HTML 再运行同一个正文解析器。
5. 两次均无正文时返回可操作错误，不把导航和页脚伪装成成功。

静态请求遇到安全重定向、匿名访问被拒或不支持的压缩编码时也进入浏览器降级；这些情况在公开内容平台中可能由普通客户端与浏览器响应差异造成。私网/保留地址、大小超限、限流和不支持的内容类型不会借浏览器绕过。

Docker 默认 seccomp 与完全清空 capabilities 会阻止 Chromium 用户命名空间沙箱。最终配置采用 Playwright 官方 seccomp profile，容器 capabilities 先全部清空再仅加入 `SYS_CHROOT`；`chromiumSandbox` 保持开启。

仅按正文长度连续两次不变会过早结束异步 API 页面。最终先有界等待 `networkidle`，再要求三次稳定采样，仍受总渲染超时约束。
